Open tools

Clinical pharmacology model explorers

Browser-based pharmacokinetic models with their equations, parameters and assumptions on the surface. Built to be checked, not trusted.

Principles

  • No machine learning. Every result is a closed-form or numerically exact solution of stated equations.
  • No dosing recommendations. These tools display calculations; they do not tell anyone what to do.
  • No hidden parameters. Values are user-supplied or explicitly flagged as illustrative, and provenance travels with the results.
  • No unearned confidence. Verification, external validation and clinical impact are tracked as separate claims, and only the first is currently established for anything here.
  • Nothing entered is transmitted. All computation happens in the page; there are no requests after load, no analytics and no third-party code.

Tools

RenalShift

Antimicrobial exposure when continuous renal replacement therapy starts, stops, or changes. Static dosing tables assume a stable circuit; real circuits clot, get paused for procedures, and get represcribed. This shows the concentration-time consequences, decomposes total clearance into non-renal, residual renal and extracorporeal components, and attributes the effect of each event by counterfactual comparison.

Governance

Each tool passes through an evidence gate before any interface work begins, and the outcome is recorded whether or not it is favourable. RenalShift failed its model-availability gate; the intended use was narrowed rather than the evidence invented, and the reasoning is written down.

  • Intended use — what these tools are and are not for
  • Landscape review — what already exists, including five corrections to an earlier, overstated draft
  • Model selection — the evidence gate and why no population model is bundled
  • Validation plan — five levels, two complete, three blocked with reasons
  • Claim language — the wording rules, including banned phrasings
  • Risk register

Verification

The numerical core is checked by 110 automated assertions, including agreement between the production matrix-exponential solver and an independently written Dormand-Prince integrator to about 4 parts in 1012, closed-form checks on every exposure metric, and mass-balance and degenerate-input cases. The suite is mutation-tested to confirm it is not vacuous. Run it with node tests/tests.js.

This establishes that the code solves the equations it claims to solve. It establishes nothing about whether those equations describe any real patient.

RenalShift model card

Last reviewed 2026-07-25. Schema version 1.0.0.

What the model is

A one- or two-compartment mammillary pharmacokinetic model with first-order elimination from the central compartment, integrated across a user-defined therapy timeline. Total clearance is treated as a step function of time:

CL_total(t) = CL_nonrenal + CL_residual(t) + CL_extracorporeal(t)

Extracorporeal clearance is computed from the prescribed circuit configuration rather than from a single lumped effluent term: 

Qp  = Qblood x (1 - haematocrit)          plasma water flow
Qf  = Qpre + Qpost + Qnet                 filtration across the membrane
DF  = Qp / (Qp + Qpre)                    pre-dilution correction
CLd = SA x Qdialysate x saturation        diffusive
CLc = SC x Qf                             convective
CL  = DF x (CLd + CLc)

SC is the sieving coefficient and SA the saturation coefficient. The interface currently sets both equal to the unbound fraction, which is an approximation: they are distinct measured quantities.

Population it applies to

None is defined. No qualified population pharmacokinetic model is bundled with this application. The parameters are supplied by the user, so the applicable population is whatever population the user's source describes — and it is the user's responsibility to know what that is.

The presets shipped in data/drugs.js are illustrative placeholders carrying an illustrative quality flag. They exist so the interface can be exercised. They are not traceable to any published model and must not be used to draw conclusions about a patient.

The reason no model is bundled is recorded in full in model-selection.md: a suitable prospective cefepime CRRT model was identified, but its full text was not retrievable in the environment where this was built, and reconstructing the missing parameters from typical literature values would have been fabrication.

Assumptions

  • Linear, time-invariant pharmacokinetics within each interval between events.
  • Constant sieving and saturation coefficients.
  • Constant protein binding, independent of concentration and time.
  • Instantaneous distribution within each compartment.
  • The pre-dilution correction is applied to the whole filter clearance rather than only to the pre-diluted stream — the standard simplification, which slightly under-predicts clearance when post-dilution replacement also runs. The application warns when both are non-zero.
  • Prescribed flows are delivered flows. Real circuits deliver less.

Not modelled

  • Membrane adsorption of drug, which is agent- and membrane-specific and can dominate for some combinations.
  • Filter performance decay over the life of the circuit.
  • Concentration- or time-dependent changes in protein binding.
  • Regional citrate anticoagulation effects on effective solute transport.
  • Sequestration by any concurrent extracorporeal circuit, including ECMO.
  • Between-patient variability of any kind. There is no population layer.

Known failure modes

  • Highly protein-bound drugs. Setting the sieving coefficient equal to the unbound fraction becomes unreliable, and adsorption is more likely to matter.
  • High filtration fraction. Above roughly 20–25% of plasma water flow, haemoconcentration invalidates the constant-sieving assumption. The application warns but still computes.
  • High dialysate flow relative to plasma water flow. Complete dialysate saturation stops being a reasonable default.
  • Recovering or deteriorating renal function. Residual renal clearance is entered as a single constant. Time-varying residual function is a planned extension and is not implemented.

The verification suite was mutation-tested to confirm it is not vacuous: removing the pre-dilution correction produced two failures, and transposing two rate constants in the compartment matrix produced six.

Intended use, restated

Teaching, exploration and scenario comparison. This application produces no dosing recommendation. It does not select a dose, rank scenarios, or judge a regimen adequate or inadequate. Where two scenarios differ it describes the difference and stops.

Full statement: intended-use.md.

Data handling

All computation happens in the page. There are no network requests after load, no analytics, no third-party scripts and no external assets. No identifying field exists: the application asks only for the physiological parameters the equations consume.

Serving any web page reveals ordinary request metadata to the host. The claim made here is about the application, not the network.
